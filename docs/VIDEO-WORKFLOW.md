# 영상 확인 — 공통 도구를 사용하는 작업 절차

0.5.0-beta.5부터 영상 처리는 별도 MCP 도구 묶음이 아닙니다. **기존 프로세스 실행·출력 조회·파일 읽기**를 조합합니다. `mac_read_file`은 이미 PNG/JPEG를 실제 이미지 블록으로 반환하므로 이미지 전용 도구도 추가하지 않았습니다. 도구는 34개에서 29개로 줄었습니다.

`scene_bridge/core.py`의 검증된 YouTube 주소 처리, yt-dlp, FFmpeg, 시각 계산 및 모아보기 생성 코드는 재사용합니다. 새 연결·서버·설치·API 키는 없습니다. `scene_bridge`는 내부 Python 모듈 이름입니다. `scene_bridge.server` MCP 어댑터는 제거했습니다. 기존 `Jobs` 클래스는 라이브러리 호환성을 위해 남아 있지만 MCP 서버와 새 CLI에서는 생성하거나 사용하지 않습니다.

## 사용자가 요청하는 방법

평소처럼 영상 주소와 보고 싶은 내용을 알려 주세요.

> 이 영상에서 도로와 건물 배치를 확인해 주세요. 먼저 대표 장면을 보고 필요한 구간만 더 자세히 봐 주세요.

로컬 영상은 **실제 파일 경로**를 알려 주시면 됩니다. 전용 `input` 폴더에 복사하거나 `local:` 별칭을 만들지 않습니다. 원본은 변경하지 않습니다.

## 에이전트가 수행하는 순서

1. `mac_status`의 `workflows.video`에서 설치된 실행 명령과 의존성 상태를 확인합니다. 운영 앱에 포함된 스크립트를 실행하므로 개발 소스를 임의로 가져와 실행하지 않습니다.
2. `mac_start_process`로 그 명령에 영상 주소/파일 경로와 옵션을 붙입니다. 주소와 경로는 각각 셸 인자로 올바르게 인용합니다. 출력 위치는 선택된 작업 폴더 안이어야 이후 파일 도구로 읽을 수 있습니다.
3. 반환된 PID로 `mac_process_output`을 호출해 JSONL 진행 상황과 실제 종료 코드를 확인합니다. `started`나 프로세스 PID만으로 완료라고 판단하지 않습니다.
4. `event=complete`와 종료 코드 0을 확인한 뒤 `manifest_path`를 `mac_read_file`로 읽습니다. 시각, 샘플링 방식, 이미지 해시가 기록되어 있습니다.
5. 같은 `mac_read_file`로 `sheet_path`를 읽어 실제 모아보기 이미지를 확인합니다. 더 자세히 볼 프레임은 `frame_paths`의 해당 파일을 읽습니다. 경로를 알아낸 것만으로 영상을 봤다고 보고하지 않습니다.
6. 부족한 구간은 같은 스크립트로 다시 추출합니다. 작업을 취소해야 하면 관측한 PID를 `mac_stop_process`에 넘깁니다. `&`/nohup/별도 데몬을 사용하지 않습니다.

명령 사용법은 `workflows.video.command`에 `--help`를 붙여 볼 수 있습니다. 개발 소스에서 직접 실행하는 예시는 다음과 같습니다. 아래의 `SOURCE`는 실제 사용자 제공 주소 또는 파일 경로로 바꿉니다.

```sh
python -B -m mac_bridge.video 'SOURCE' --output './frames' --count 6
python -B -m mac_bridge.video 'SOURCE' --output './frames' --start 60 --end 120 --count 6
python -B -m mac_bridge.video 'SOURCE' --output './frames' --timestamps 12 45 90 --max-edge 1280
```

실제 앱에서는 위 개발용 Python 경로를 가정하지 말고 **`mac_status`가 반환한 실행 명령**을 사용합니다. 입력 URL의 `t`/`start` 값은 자동 적용하지 않습니다. 구간이나 지정 시각은 옵션으로 전달하세요. `--timestamps`와 `--start/--end`는 함께 쓸 수 없습니다.

## 결과와 진행 상태

표준 출력은 `started → progress → complete` 또는 `error/cancelled` JSON 행입니다. FFmpeg 로그, 재생용 서명 URL, 쿠키, 이미지 base64를 텍스트로 출력하지 않습니다. 최종 결과만 파일 경로를 반환합니다.

기본 출력은 **현재 작업 폴더의 `.mac-bridge-artifacts/video/video-<고유 ID>/`**입니다. 선택한 `--output`에도 매번 고유 하위 폴더를 만들며 이전 결과를 덮어쓰지 않습니다.

```text
video-<고유 ID>/
  manifest.json
  contact-sheet.jpg
  frame-01.jpg
  frame-02.jpg
  ...
```

이미지와 manifest는 일반 파일이어서 서버를 재시작해도 유지됩니다. 동일 작업 중복 요청을 자동 재사용하는 별도 서버 캐시나 작업 ID 조회는 더 이상 없습니다. 반복 요청은 새 결과를 만듭니다. 이미 있는 결과는 일반 파일 읽기로 재사용하세요.

일반 오류와 SIGINT/SIGTERM 취소에서는 **이번 실행의 임시 폴더만 정리**합니다. 성공한 결과와 사용자의 원본·다른 파일은 자동 삭제하지 않습니다. SIGKILL/정전 등 정상 정리 기회가 없는 강제 종료는 임시 폴더를 남길 수 있으며, 그런 `.partial-video-*` 폴더는 manifest가 있더라도 성공 결과로 사용하면 안 됩니다. 최종 `video-<ID>` 폴더와 `complete` 이벤트·정상 종료를 확인하세요.

최대 4시간 영상, 한 번에 12프레임, 최대 이미지 변 1920px, 작업 예산 240초를 유지합니다. 프레임은 기존 디코더의 개별 시간·용량 제한도 적용합니다. 동일 출력 폴더는 한 번에 한 프로세스만 사용하며 별도 대기열을 만들지 않습니다. 성공 결과 보관량이 한도(512 MiB에서 다음 실행의 최대 48 MiB를 예약)에 도달하면 기존 파일을 지우지 않고 중단합니다. 필요한 결과를 옮기거나 명시적으로 정리한 후 재실행하세요.

## 공통 권한·취소·로그

영상 시작도 일반 명령이므로 `ask/always`, 작업 기록, PID 소유권 확인, 업데이트 대기 규칙을 그대로 따릅니다. `mac_pause`는 새 영상 명령을 막고 기존에 시작한 프로세스 중지를 시도합니다. 이전의 독립 영상 도구처럼 pause와 별개로 계속 실행되지 않습니다. 앱 업데이트는 실행 중인 프로세스가 끝날 때까지 대기합니다.

MCP 요청 로그에는 일반 프로세스 호출 요약과 응답 크기를 기록합니다. 영상 진행 결과는 프로세스 출력으로 조회합니다. 권한이 있는 사용자라도 읽은 영상 제목·파일 경로·화면은 민감할 수 있으므로 로그 전체를 공개하지 마세요. 이 구조는 OS 샌드박스가 아닙니다.

삭제/비공개/DRM/봇 차단을 우회하지 않으며 브라우저 쿠키를 읽지 않습니다. 원격 미디어는 기존 검증된 YouTube HTTPS 처리 경로만 사용합니다. YouTube 서비스 변화로 추출이 실패할 수 있습니다. 원본을 사용할 권리가 있을 때 로컬 영상을 전달할 수 있습니다.

모아보기는 **샘플 프레임**이지 전체 영상 시청이나 의미 기반 장면 판별 결과가 아닙니다. 표시한 시각은 요청 시각이며 프레임 단위 정확도를 보장하지 않습니다. `decoded_source_pts_seconds`와 원본 시작 오프셋을 함께 고려하세요.

## 이전 버전에서 바뀌는 것

제거된 MCP 도구는 `start_extraction`, `get_extraction`, `get_frame`, `list_local_videos`, `bridge_status`입니다. 상태는 `mac_status`, 목록과 결과는 일반 파일 도구, 실행/진행/취소는 일반 프로세스 도구로 통합했습니다. 설치된 앱을 갱신한 뒤 연결의 도구 목록을 Refresh해야 오래된 도구가 추천되지 않습니다.

기존 앱 데이터의 `input`, `output` 및 과거 추출물은 삭제하지 않습니다. 새 결과는 작업 폴더에 저장됩니다. 이전 결과가 파일 도구 범위 밖에 있다면 필요한 파일만 명시적 요청에 따라 작업 폴더로 복사합니다. 자동으로 개인 영상 폴더를 탐색하거나 대량 이전하지 않습니다.

## 실제 검증

`tests/test_video_workflow.py`는 시각/용량/경로/출력 보존·원본 변경 감지·취소 정리를 검사합니다. 별도 부모/디코더 프로세스에 SIGTERM을 보내 자식 종료·회수를 검증합니다. 네트워크 응답을 모의 처리한 검사는 온라인 YouTube 성공으로 간주하지 않습니다.

`tests/smoke_mcp.py`는 실제 MCP → 일반 프로세스 → FFmpeg로 합성 테스트 영상의 프레임을 만들고, 기존 `mac_read_file`이 모아보기·개별 프레임을 **실제 디코딩 가능한 이미지**로 돌려주는 것을 검사합니다. 서버 재시작 후 결과 재읽기, pause, 구 도구 제거도 확인합니다. 실제 사용자의 영상이나 온라인 YouTube를 사용하는 검사는 아닙니다.
