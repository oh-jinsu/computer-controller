# Mac Bridge

**ChatGPT에서 내 Mac의 파일, 터미널, Chrome과 영상 프레임을 다루는 개인용 연결 앱입니다.**

사용자는 **릴리스 ZIP을 내려받아 `Mac Bridge.app`을 실행**합니다. Homebrew, Python, Node, Git을 따로 설치하거나 소스 코드를 내려받을 필요가 없습니다. 필요한 실행 환경은 앱에 포함되어 있습니다. Google Chrome은 브라우저 기능을 사용할 때만 별도로 필요합니다.

[릴리스 / 다운로드](https://github.com/oh-jinsu/mac-bridge/releases) · [기존 설치에서 이전하기](#기존-설치에서-이전하기) · [문제 해결](#문제-해결) · [개발자 문서](#개발자-문서)

> **배포 상태 — 2026-09-23**
>
> `0.5.0-beta.2` 앱은 Developer ID 서명, Apple 공증 확인서 검증, Gatekeeper 검사를 통과했습니다. 배포 ZIP과 업데이트 목록의 서명·업로드도 검증했습니다.
>
> **현재 저장소는 비공개이며 릴리스는 Draft입니다. 아직 누구나 다운로드할 수 있는 공개 정식 배포는 아닙니다.** 아래는 검증된 앱을 전달받거나, 게시된 릴리스에 접근할 수 있는 사용자를 위한 설치 절차입니다. 다운로드 페이지가 보이지 않거나 파일이 없으면 공개 배포를 기다려 주세요. `Source code`를 설치 파일 대신 받지 마세요.
>
> 공증 여부는 **해당 릴리스의 해당 파일**에 적용됩니다. 이전 미리보기나 직접 빌드한 앱까지 모두 공증된 것은 아닙니다. 실제 공개 업데이트 경로와 별도 Mac에서의 첫 설치는 추가 검증 대상입니다.

## 어떤 일을 할 수 있나요?

| 기능 | 현재 제공하는 작업 |
| --- | --- |
| 파일·개발 | 선택한 작업 폴더 조회, 텍스트·실제 이미지 읽기, 파일 편집, 명령 실행과 결과 확인 |
| Chrome | 페이지 열기·읽기·입력·클릭·캡처, 탭과 콘솔·네트워크 요청 정보 확인 |
| 앱 화면 | 요청한 앱의 창 목록과 지정 창의 실제 화면 캡처 |
| 영상 확인 절차 | 공통 프로세스·파일 도구로 YouTube/로컬 영상의 실제 프레임 추출·이미지 확인 |
| 작업 인계 | 명시적으로 작성한 작업 요약 저장·불러오기 |

**아직 제공하지 않는 기능:** 브라우저 파일 업로드 도구, 사용 중인 창과 분리된 자동화 전용 백그라운드 창, 일반 Mac 앱의 마우스·키보드 조작, 모든 ChatGPT 대화의 자동 동기화. 따라서 YouTube 영상 업로드 같은 전체 작업이 완성됐다고 안내하지 않습니다. 사이트의 추가 인증이나 접근 제한을 자동으로 우회하지도 않습니다.

## 처음 설치하기 — 순서대로 따라 하세요

### 1. 내 Mac과 계정을 확인하세요

이 릴리스는 **Apple Silicon(M1 이후 M 시리즈) / macOS 26 이상**용입니다. Mac 왼쪽 위 ** → 이 Mac에 관하여**에서 칩과 macOS 버전을 확인하세요. Intel Mac, Windows, 이전 macOS용 설치 파일은 아직 없습니다.

ChatGPT에서 **개발자 모드의 사용자 지정 MCP 연결**과 **Secure MCP Tunnel**을 사용할 수 있어야 합니다. 계정·요금제·워크스페이스 정책에 따라 제공 여부가 다릅니다. 회사나 학교 계정은 관리자 권한이 필요할 수 있습니다. 기능이 보이지 않으면 앱 재설치보다 먼저 [OpenAI의 연결 조건](https://developers.openai.com/plugins/deploy/connect-chatgpt)을 확인하세요.

설치자는 Xcode, Apple Developer Program 가입, Developer ID 인증서, 업데이트 서명키가 필요하지 않습니다. 이들은 **배포자가 준비하는 것**입니다. ChatGPT 및 연결 서비스의 이용 조건·이용료는 앱 설치와 별개입니다.

### 2. ZIP을 받고 앱을 옮겨 실행하세요

1. [Releases](https://github.com/oh-jinsu/mac-bridge/releases)에서 사용할 버전의 설명과 지원 환경을 확인하세요.
2. **Assets**를 펼치고 `Mac-Bridge-<버전>-macos26-arm64.zip`을 받으세요. 예를 들어 현재 공증된 베타의 파일명은 `Mac-Bridge-0.5.0-beta.2-macos26-arm64.zip`입니다. `Source code (zip)`과 `Source code (tar.gz)`는 개발자용 소스이며 설치 파일이 아닙니다.
3. 받은 ZIP을 두 번 클릭해 압축을 푸세요. 안에 있는 **`Mac Bridge.app`**을 Finder의 **응용 프로그램** 폴더로 옮기세요. 처음 실행하기 전에 옮겨 두면 업데이트 때도 같은 설치 위치를 사용할 수 있습니다.
4. 옮긴 앱을 두 번 클릭하세요. 첫 실행에 인터넷에서 받은 앱인지 묻는 정상 확인창이 나오면 배포자와 파일 출처를 확인한 뒤 **열기**를 선택하세요.
5. 화면 위 메뉴 막대에 **`MB`**가 표시됩니다. 설정 창이 보이지 않으면 **MB → 설정…**을 누르세요. 메뉴 막대 앱이므로 Dock 아이콘이나 큰 창이 계속 보이지 않아도 정상입니다.

`appcast.xml`, 체크섬, 빌드 출처 파일은 일반 사용자가 실행하는 파일이 아닙니다. 앱 ZIP만 받으시면 됩니다. **악성 소프트웨어·손상·공증 확인 실패로 차단되는 경우에는 보안 설정을 끄지 말고 중단**한 뒤 [문제 해결](#문제-해결)을 확인하세요. [Apple의 앱 열기 안내](https://support.apple.com/ko-kr/102445)

### 3. 처음 한 번, 내 연결 정보를 준비하세요

**이미 My Mac 터널을 사용하고 계시면 이 단계를 건너뛰고 [기존 설치에서 이전하기](#기존-설치에서-이전하기)를 따르세요. 새 터널이나 새 키를 만들 필요가 없습니다.**

새 사용자에게는 다음 두 가지가 필요합니다.

| 준비할 정보 | 의미 |
| --- | --- |
| **터널 ID** | 내 ChatGPT와 내 Mac을 연결할 터널의 `tunnel_…` 식별자입니다. 터널의 표시 이름이 아닙니다. |
| **Runtime API 키** | 내 Mac의 터널 클라이언트가 OpenAI에 접속할 때 사용하는 실행용 키입니다. 앱 서명키나 Apple 비밀번호가 아닙니다. |

[OpenAI Secure MCP Tunnel 안내](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)의 **Platform tunnel settings** 링크를 여세요. 사용할 조직에서 터널을 만들고 **실제로 사용할 ChatGPT 워크스페이스를 연결 대상에 포함**한 뒤 ID를 복사하세요. 터널 생성에는 `Tunnels: Read + Manage`, 실행과 ChatGPT에서의 선택에는 `Read + Use` 권한이 필요합니다. 실행용 키는 해당 조직에서 필요한 권한으로 준비하세요. 관리자 키를 앱의 일상 실행용으로 넣지 마세요.

**각 사용자는 자신의 터널과 키를 사용합니다. 배포자의 터널·키를 공유해서 쓰지 않습니다.** Mac Bridge 앱에는 터널 생성 화면이 없으므로 최초 준비는 OpenAI 쪽에서 진행합니다. 공식 안내의 로컬 프로그램 설치 명령은 Mac Bridge 앱 사용자에게 다시 필요한 절차가 아닙니다. 클라이언트는 앱에 포함되어 있습니다.

**API 키는 앱의 키 입력란에만 넣으세요.** ChatGPT 메시지, GitHub 이슈, 스크린샷에 올리지 마세요.

### 4. 앱에 연결 정보를 저장하세요

**MB → 설정…**에서 다음 항목을 채우세요.

| 화면의 항목 | 입력하거나 선택할 내용 |
| --- | --- |
| **터널 ID** | 3단계에서 준비한 `tunnel_…` ID |
| **작업 폴더** | **선택…**을 눌러 작업을 맡길 폴더 선택. 예: 프로젝트를 모아 둔 `~/dev` 또는 별도의 작업 폴더 |
| **Runtime API 키** | 처음 연결할 때 실행용 키 입력. 기존 설정을 가져왔고 키체인에 키가 있으면 비워 두기 |
| **요청된 Mac 작업 항상 허용** | 처음에는 해제한 상태로 동작을 확인하는 것을 권장합니다. 체크하면 요청별 Mac 승인창을 생략하며, 선택은 저장됩니다. |
| **평소 Chrome 로그인 상태 사용** | 평소 로그인한 Chrome으로 작업하려는 경우에만 체크. 추가 설정은 아래 Chrome 항목 참고 |
| **서명된 업데이트 자동 확인·다운로드** | 켜 두면 게시된 최신 정식 버전을 확인합니다. 베타 초안은 자동 업데이트 대상이 아닙니다. |

**저장 → 연결 시작**을 누르세요. 새 키를 저장하거나 기존 키를 사용할 때 macOS 키체인 확인창이 나타날 수 있습니다. 요청한 앱과 항목을 확인하세요. **앱 사용자가 업데이트 서명용 비밀키를 입력하는 절차는 없습니다.**

메뉴에 **Mac Bridge · 서버 실행 중**이 표시되면 로컬 서버가 응답하고 있는 것입니다. ChatGPT에서 사용할 수 있는지는 다음 단계의 실제 도구 호출로 확인합니다. 연결 중에는 설정을 바꾸지 않도록 되어 있으므로 변경할 때는 **연결 중지 → 설정 수정·저장 → 연결 시작** 순서로 진행하세요.

> **권한을 이해하고 선택하세요.** 작업 폴더는 파일 도구의 범위입니다. 터미널 명령은 Mac 사용자 권한으로 이 폴더 밖과 네트워크에도 접근할 수 있어 보안 샌드박스가 아닙니다. ‘항상 허용’은 요청하지 않은 삭제·게시·전송에 대한 포괄적 동의가 아니며, macOS·Chrome·ChatGPT 자체의 권한 확인도 없애지 않습니다.

### 5. ChatGPT에 My Mac을 추가하세요

앱을 실행한 채로 ChatGPT에서 진행하세요.

1. **설정 → 보안 및 로그인 → 개발자 모드**를 켜세요. 메뉴가 없으면 계정·워크스페이스의 사용 권한을 먼저 확인하세요.
2. [플러그인](https://chatgpt.com/plugins)에서 **+**를 눌러 연결을 추가하세요.
3. 이름을 **My Mac**, 설명을 예를 들어 **내 Mac의 파일·브라우저·영상 작업**으로 입력하세요.
4. **Connection → Tunnel**을 선택하고 앱에 입력한 것과 **같은 터널**을 선택하거나 같은 ID를 넣으세요. 임의의 로컬 주소나 공개 MCP URL을 만들 필요는 없습니다.
5. 연결을 생성하고 도구 목록에 **`mac_status`**, **`mac_start_process`**, **`mac_read_file`**가 있는지 확인하세요.
6. 새 대화에서 도구 메뉴 또는 `@` 목록의 **My Mac을 실제로 선택**하세요. 이름을 글자로만 입력하는 것과 도구를 선택하는 것은 다릅니다.

화면 이름은 ChatGPT 버전에 따라 달라질 수 있습니다. [최신 공식 연결 절차](https://developers.openai.com/plugins/deploy/connect-chatgpt)를 함께 참고하세요. 이 방식은 각 사용자가 자신의 비공개 MCP를 연결하는 방식이며, **GitHub에서 앱을 공개하는 것과 ChatGPT 플러그인 스토어에 공개 등록하는 것은 별개**입니다.

### 6. 읽기 전용 테스트로 확인하세요

My Mac을 선택한 대화에 아래 문장을 보내세요.

```text
My Mac의 mac_status를 실제로 호출해 연결 상태와 영상 처리 의존성을 보여 주세요.
파일 수정, 명령 실행, 프로그램 설치, 화면 캡처는 하지 마세요.
```

`mac_status`에서 버전, 작업 폴더, `desktop_connected: true`를 확인하세요. 앱 설치본이라면 `independent_runtime: true`, `source_checkout_is_runtime: false`도 표시됩니다. **이 값이 아직 0.4.0이거나 독립 실행 표시가 없다면 이전 터미널 서버에 연결된 것일 수 있습니다.**

그다음 파일 목록만 확인해 보세요.

```text
선택한 작업 폴더의 바로 아래 파일·폴더 이름만 보여 주세요.
파일 내용은 읽지 말고 아무것도 변경하지 마세요.
```

이 두 테스트가 끝나면 필요한 작업을 요청하시면 됩니다. 상태 조회 성공만으로 브라우저 로그인, 앱 화면 권한, 파일 쓰기까지 모두 시험한 것은 아닙니다.

## 영상 링크를 보여 주는 방법

영상 주소와 확인하고 싶은 내용을 그대로 요청하세요. 로컬 영상은 **실제 파일 경로**를 알려 주시면 되며 전용 폴더에 복사할 필요가 없습니다.

```text
이 영상에서 도로와 건물 배치를 확인해 주세요.
먼저 대표 프레임을 보고, 필요한 구간만 추가로 추출해 주세요.
```

**0.5.0-beta.5에서는 영상 전용 MCP 도구를 제거하고 공통 도구로 통합했습니다.** 내부적으로 `mac_start_process`로 앱에 포함된 영상 스크립트를 실행하고, `mac_process_output`으로 진행·종료를 확인한 다음 `mac_read_file`로 실제 이미지를 읽습니다. 도구 수는 34개에서 29개로 줄었으며 새 이미지 도구나 연결은 추가하지 않았습니다. 사용자가 추출 명령을 직접 만들 필요는 없습니다.

원본은 변경하지 않습니다. 새 결과는 작업 폴더의 `.mac-bridge-artifacts/video/`에 저장되며 앱 재시작 후에도 일반 파일로 읽을 수 있습니다. 예전 앱의 `input`/`output` 파일은 지우지 않습니다. 추출 시간·프레임 수 제한과 개인정보·접근 제한 처리는 유지합니다. [영상 작업 절차·취소·출력 파일](docs/VIDEO-WORKFLOW.md)

## 평소 Chrome으로 작업하기

브라우저 기능이 필요할 때만 설정하세요. 파일·터미널·영상 작업에는 이 설정이 필요하지 않습니다.

1. 앱의 **연결 중지 → 설정…**에서 **평소 Chrome 로그인 상태 사용**을 체크하고 저장하세요.
2. 평소 사용하던 Google Chrome을 열고 주소창에 `chrome://inspect/#remote-debugging`을 입력하세요.
3. **Allow remote debugging for this browser instance**를 허용하세요. 해당 항목이 없는 Chrome은 이 모드의 지원 조건을 확인해야 합니다. 현재 경로는 Chrome 144+의 연결 방식을 사용하며, 개발 Mac에서는 Chrome 153으로 시험했습니다.
4. 앱의 **연결 시작**을 누르고, ChatGPT에 필요한 사이트 작업을 요청하세요. Chrome이 연결 허용창을 표시하면 연결 대상을 확인하고 직접 승인하세요.

**추가 Chrome 확장 설치, 개인 프로필 복사, 쿠키 내보내기는 필요하지 않습니다.** Chrome이 꺼져 있으면 앱이 일반 Chrome을 실행하는 경로를 사용합니다. 로그인 만료나 추가 인증은 사용자가 해당 사이트에서 직접 처리해야 합니다.

```text
평소 Chrome으로 네이버 메인 페이지를 열고 로그인 상태만 확인해 주세요.
메일을 보내거나 글을 게시하지 말고, 작업 후 browser_close로 연결을 닫아 주세요.
```

**현재 베타는 작업 탭이 사용 중인 Chrome 창에 열릴 수 있습니다.** 별도 백그라운드 창과 포커스 비간섭은 아직 구현하지 않았습니다. 방해받기 곤란한 작업 중에는 브라우저 자동화를 요청하지 마세요. `browser_close`는 개인 Chrome의 연결만 해제하며 사용자 창과 작업 탭을 닫지 않습니다.

체크를 끄면 **평소 로그인과 분리된 전용 프로필**을 사용합니다. 기본은 화면 없는 웹 테스트 모드라 평소의 네이버·Google 로그인이 자동 공유되지 않습니다. [브라우저 상세 설명](docs/BROWSER-CONTEXT.md)

## 다른 앱의 화면을 확인하려면

**MB → 화면 기록 권한…**을 누르고, 안내에 따라 macOS **시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 기록**에서 해당 앱의 화면 기록을 허용하세요. macOS가 재시작을 요구하면 Mac Bridge를 종료하고 다시 실행하세요. 운영체제 버전에 따라 항목 이름이 조금 다릅니다.

이 권한은 Godot 등 다른 앱의 창을 촬영할 때 필요합니다. 일반 파일 조회에는 필요하지 않으며, **브라우저 페이지 캡처와 Mac 창 캡처는 서로 다른 기능**입니다. [Apple 권한 안내](https://support.apple.com/guide/mac-help/mchld6aa7d23/mac)

## 매일 실행하고 종료하는 방법

설정을 마친 뒤에는 **응용 프로그램의 Mac Bridge를 실행 → ChatGPT에서 My Mac 선택**만 하시면 됩니다. 설정이 저장되어 있으면 앱 시작 시 연결을 시도합니다. 터미널을 열어 둘 필요는 없습니다.

설정 창을 닫아도 메뉴 막대의 앱은 계속 실행됩니다. 연결만 끊으려면 **MB → 연결 중지**, 앱까지 끝내려면 **MB → 종료**를 선택하세요. 작업 중 중지하면 실행하던 프로세스가 종료될 수 있으니 먼저 작업 완료를 확인하세요.

Mac이 켜져 있고 잠들지 않은 상태로 네트워크에 연결되어 있어야 원격 요청을 처리할 수 있습니다. 앱 종료, 로그아웃, 잠자기, 네트워크 단절 상태에서는 즉시 응답할 수 없습니다. Mac 부팅·로그인 때 앱을 자동 실행하는 설정은 현재 앱이 자동으로 등록하지 않습니다.

## 자동 업데이트

**서명된 업데이트 자동 확인·다운로드**를 켜 두면, 앱이 실행 중일 때 주기적으로(설정된 간격은 6시간) 최신 **정식 릴리스**를 확인합니다. 지금 확인하려면 **MB → 업데이트 확인…**을 선택하세요. 공개 배포 후 사용자는 GitHub 로그인이나 `git pull`을 할 필요가 없습니다.

앱은 업데이트 목록과 파일 서명을 검사합니다. 적용 시에는 진행 중인 명령·영상 추출·브라우저 연결이 끝나기를 기다립니다. 브라우저 작업이 끝났다면 `browser_close`로 연결을 해제하세요. 설치·재시작 안내가 표시되면 진행 중인 작업을 확인한 뒤 따르세요. 업데이트 적용 순간에는 연결이 잠시 끊길 수 있습니다.

**저장소가 비공개이거나 게시된 정식 릴리스가 없으면 업데이트를 받을 수 없습니다.** Draft·베타(prerelease)는 최신 안정판 경로에서 제공하지 않습니다. 이 경우 기존 앱은 그대로 사용할 수 있으며 GitHub 키를 새로 입력할 필요는 없습니다. 서명 실패나 다운로드 실패 시 검증을 끄고 설치하지 마세요.

설정은 앱 밖에 보관하며 이전 앱 사본도 남깁니다. 다만 **새 버전 실행 실패 후 자동 복구는 구현하지 않았습니다.** 이전 사본은 메뉴 **이전 실행본 보기**에서 수동 복구용으로 확인할 수 있습니다.

## 기존 설치에서 이전하기

이미 Scene Bridge 또는 터미널 버전 Mac Bridge를 사용 중인 분을 위한 절차입니다.

1. 기존 실행 터미널에서 **Ctrl+C**로 중지하세요. 같은 터널의 서버 두 개를 동시에 실행하지 마세요.
2. 새 `Mac Bridge.app`을 설치 위치에서 열고 **MB → 설정… → 기존 설정 가져오기…**를 누르세요.
3. 예전에 실행하던 **`mac-bridge` 폴더 자체**를 선택하세요. `.state` 하위 폴더를 선택하는 것이 아닙니다.
4. 가져온 작업 폴더·승인 모드·브라우저 선택을 확인하고 **연결 시작**을 누르세요. 터널 ID와 키체인의 기존 Runtime 키를 재사용합니다.
5. ChatGPT의 기존 My Mac 연결을 **Refresh**하고 새 대화에서 6단계의 상태 테스트를 실행하세요.

앱 설정이 이미 존재하면 가져오기는 덮어쓰지 않고 중단합니다. 키체인에서 새 실행본의 접근 확인을 요청할 수 있습니다.

**이전 영상·추출 결과·작업 요약·로그·파일 백업은 자동 복사하거나 삭제하지 않습니다.** 기존 폴더를 바로 지우지 마세요. 새 영상 작업은 실제 파일 경로로 요청하며, 필요한 이전 결과·자료만 별도로 옮기세요. 기존의 일시 중지 상태도 보존됩니다.

## 내 파일과 설정은 어디에 있나요?

Finder에서 **이동 → 폴더로 이동…**(단축키 `Shift+Command+G`)을 선택하고 아래 경로를 붙여 넣으세요.

| 종류 | 앱 설치본의 위치 |
| --- | --- |
| 설정·작업 데이터 | `~/Library/Application Support/Mac Bridge` |
| 로컬 영상 원본 | 사용자가 지정한 파일 경로. 이전 버전의 `~/Library/Application Support/Mac Bridge/input`은 그대로 보관 |
| 새 추출 결과 | 선택한 작업 폴더의 `.mac-bridge-artifacts/video/` 또는 지정한 출력 폴더 |
| 이전 추출 결과 | `~/Library/Application Support/Mac Bridge/output` — 자동 삭제하지 않음 |
| 파일 도구의 수정 전 백업 | `~/Library/Application Support/Mac Bridge/.state/file-backups` |
| 저장한 작업 요약 | `~/Library/Application Support/Mac Bridge/.state/contexts` |
| 로그 | `~/Library/Logs/Mac Bridge` — **MB → 로그 보기**로도 열 수 있음 |

`~`는 현재 Mac 사용자의 홈 폴더입니다. API 키는 키체인에 보관합니다. 키체인 내용이나 `.state` 폴더 전체를 지원 요청에 첨부하지 마세요. 파일·화면·페이지를 읽는 도구의 결과는 ChatGPT 대화로 전달될 수 있습니다. 로컬 기록 역시 같은 사용자 권한의 다른 프로그램으로부터 완전히 격리되는 것은 아닙니다.

개발 소스와 앱 실행본은 별개입니다. **앱 버전을 실행 중이라면 `~/dev/mac-bridge` 같은 소스를 수정해도 현재 앱의 코드가 바뀌지 않습니다.** 파일 도구는 실행 중인 앱과 내부 상태를 보호하되 별도의 작업 소스는 허용합니다. 단, `.env`, 키 파일, 일부 내부 경로와 심볼릭 링크에는 별도의 제한이 있습니다.

## 문제 해결

| 증상 | 먼저 확인할 일 |
| --- | --- |
| 다운로드 페이지가 404이거나 설치 ZIP이 없음 | 저장소 접근 권한, 공개 전환과 릴리스 게시 여부를 확인하세요. Draft는 일반 다운로드가 아닙니다. |
| 앱이 손상됐거나 개발자·공증을 확인할 수 없다고 나옴 | 릴리스의 공증 안내와 지원 OS를 확인하고 공식 ZIP을 다시 받으세요. 계속되면 중단하고 오류 문구를 알려 주세요. Gatekeeper를 끄거나 격리 속성을 제거하지 마세요. |
| 앱 창이 안 보임 | 화면 위 **MB → 설정…**을 여세요. 메뉴 막대 앱입니다. |
| 서버는 실행되는데 ChatGPT 연결 실패 | 터널 ID, 실행용 키의 Read + Use 권한, 터널에 연결한 ChatGPT 워크스페이스를 확인하세요. |
| 이 대화에서 도구가 안 보임 | 연결 상세 화면에 도구가 있는지 확인하고 Refresh 후 새 대화에서 My Mac을 선택하세요. 먼저 재설치하지 마세요. |
| 여전히 0.4.0이 응답함 | 예전 터미널 서버가 켜져 있는지 확인하세요. 현재 대화가 새 앱에 연결됐다고 단정하지 마세요. |
| 파일 작업 거부 | 실제 작업 폴더와 요청 경로를 확인하세요. 승인 모드와 경로 제한은 서로 다른 설정입니다. |
| 밖에서 작업 중 승인 대기 | ‘항상 허용’을 선택했는지 확인하세요. 이 설정은 Mac의 로컬 승인창만 생략합니다. |
| Chrome 연결 실패 또는 로그인 안 됨 | 개인/전용 모드, remote debugging 허용, Chrome 연결 확인창, 해당 프로필의 로그인 상태를 확인하세요. |
| 앱 창 캡처 실패 | 화면 기록 권한과 대상 앱의 창이 실제로 열려 있는지 확인하세요. |
| 업데이트 확인 실패 | 정식 공개 피드가 아직 없을 수 있습니다. 네트워크·배포 상태를 먼저 확인하고 기존 앱을 유지하세요. |
| `mac_pause` 이후 작업이 계속 차단됨 | 보존된 일시 중지는 ‘연결 중지’와 다릅니다. 현재 베타에는 앱 UI의 별도 일시 중지 해제 버튼이 없고 재시작만으로도 해제되지 않습니다. 일반적인 사용 종료에는 **MB → 연결 중지**를 사용하고, 이미 일시 중지했다면 상태와 로그의 오류 문구로 문의하세요. |

문의할 때는 **앱 버전, macOS 버전, 칩 종류, 하려던 작업, 마지막 오류 문구**를 알려 주세요. API 키·개인 메일·화면 전체를 보내지 않아도 됩니다.

## 요청·응답 로그

로그 개선이 포함된 소스/앱에서는 **도구 이름·대상 요약·승인 단계·성공/실패·소요 시간**을 요청별로 볼 수 있습니다. 5초 이상 걸리는 요청은 진행 중 표시도 남깁니다. 메일 본문, 입력 텍스트, 파일 원문, 키와 이미지 데이터는 그대로 로그에 넣지 않습니다.

사람이 읽는 로그는 실행 터미널 또는 앱의 **MB → 로그 보기**, 구조화된 기록은 실행 데이터 폴더의 `.state/request-logs/requests.jsonl`에서 확인합니다. [로그 항목·비식별화 범위·저장 위치](docs/LOGGING.md)를 참고하세요. 실행 중인 이전 프로세스와 이미 배포된 앱은 소스만 수정해서 바뀌지 않으며, 다음 재시작/새 릴리스 적용이 필요합니다.
